# CoffeeCall Code Analysis Plan

## Objective
Identify all hardcoded values (strings, numbers, colors) that should be moved to appropriate constants files.

## Scope
- Scan all Swift files in `/Users/development/Documents/CoffeeCall/apps/frontend/Coffee_Call/`
- Check against existing constants:
  - AppStrings.swift for string constants
  - AppConstants.swift for layout/radar/animation constants  
  - Color+Extensions.swift for semantic color tokens
  - Font+Extensions.swift for font tokens
  - Design/design-tokens.md for design system reference

## Methodology
1. Search for hardcoded string literals not using AppStrings
2. Search for hardcoded numeric values not using AppConstants
3. Search for hardcoded color values not using semantic tokens from Color+Extensions
4. Document findings with file paths and line numbers
5. Provide recommendations for refactoring

## Current State Assessment
Based on recent refactoring and standardization passes:
- **Completed**: DiscoveryScreen, DriftDetailScreen, ManageDriftScreen, ProfileScreen, and EditProfileScreen have been fully standardized.
- **Completed**: All hardcoded layout, spacing, and typography values in core screens have been replaced with AppConstants tokens.

- **Completed**: Missing icons (ellipsis, info, etc.) have been moved to AppIcons.
- **Completed**: Mock data has been centralized in AppConstants.MockData.

## Priority Ranking

### High Priority (Should be moved immediately)
1. Mock data in DiscoveryViewModel.swift - affects development/testing consistency
2. Hardcoded color values in Color+Extensions.swift - defeats the purpose of semantic tokens
3. Frequently used padding/spacing values that appear in AppConstants already but are ignored

### Medium Priority
1. Animation values that are already well-organized in AnimationSystem.swift but not consistently used
2. Font sizes and weights that could use the Font+Extensions helpers
3. Corner radius values that have equivalents in design tokens

### Low Priority
1. One-off values used only once or twice
2. Values that are already reasonably encapsulated
3. Truly constant values that are unlikely to change
