## Pre-Implementation Gate

Before coding a UI change:

1. State which active spec you will follow.
2. List any conflicts found in active docs.
3. Identify the files you expect to change.
4. Confirm route behavior for navigation actions.
5. Wait for approval if the user requested confirmation.

## Product Guardrails

- Around must not expose people for unsolicited contact.
- Drifts are the unit of action.
- `See nearby Drifts` routes to the Drifts listing.
- Center Create remains reserved for future Create design work.
- Chat only appears after joining or hosting a Drift.

## Design Guardrails

Follow `docs/current/DESIGN.md`.

The active Around screen must include:

- Large floating glass header.
- Spacious ambient radar.
- Circular refresh control.
- Drift context card.
- Full two-row interests grid.
- Floating glass bottom navigation.

Do not replace this with archived screen patterns.
